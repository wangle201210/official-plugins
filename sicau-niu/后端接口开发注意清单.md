# 后端接口开发注意清单（交付后端团队）

> 项目：川农 120「寻牛」微信小程序
> 前提：自建容器部署（Docker Compose：Nginx + API + MySQL + Redis），**不使用对象存储**：激活照片直传后端存本地持久化卷，静态资源（地图瓦片/皮肤/徽章）由 Nginx 托管（强烈建议前面套一层按量 CDN 回源，见 §4 带宽预估）。
> 前端侧规格见《方案B-自绘校园地图与经纬度映射规格.md》。

## 1. 全局约定

| 项 | 约定 |
|---|---|
| 坐标系 | **全链路 GCJ-02**，接口出入参一律 GCJ-02，禁止 WGS-84 混入 |
| 鉴权 | 登录后签发 JWT（含 userId/openid），Header `Authorization: Bearer`；JWT 有效期 7 天，静默续期 |
| 时间 | 全部以**服务器时间**为准（每日限次、牛上线时间、签到日界）；日界 = 北京时间 00:00 |
| 数值 | 草量、经验、喂养次数等**全部服务端计算与校验**，前端上送的数值仅作展示对账，永不采信 |
| 幂等 | 所有写接口支持客户端 `requestId` 去重（网络重试不重复扣草/重复激活） |
| 错误码 | 统一结构 `{ code, message, data }`；业务错误用语义码（如 `GRASS_NOT_ENOUGH` / `DAILY_LIMIT` / `TOO_FAR`），前端按码做文案 |
| 分页 | 列表统一 cursor 分页，禁止 offset 深翻页 |
| 资源分流 | **视觉资源（徽章/卡框/皮肤序列帧/地图瓦片）= Nginx 托管的静态文件（外套 CDN），接口只回 ID 与状态**；**内容数据（卡片文案+历史照片、校史金句）= 全部走接口**（活动期内会勘误，不能依赖小程序发版）；静态资源基地址由 `/config` 下发，前端不许硬编码，方便随时切 CDN |
| 位置保密 | **未激活牛的精确坐标是服务端机密，任何接口任何字段不得下发**（含管理端误暴露）；客户端只能拿到模糊区域。这是"寻牛"玩法成立的前提 |

## 2. 接口清单（v1）

### 2.0 基础
| 接口 | 方法 | 说明 | 注意 |
|---|---|---|---|
| `/config` | GET | 启动时拉取一次的全局配置：静态资源基地址、**地图标定数据 `calibration`（仿射矩阵+原点，由前端标定脚本产出后录入）**、徽章/皮肤元信息列表（id/名称/解锁条件文案）、活动阶段开关、激活距离阈值等 | **整个"不发小程序版热更"机制的总开关**：美术改图重标定、加徽章、改文案、调阈值全靠它；带版本号，客户端可缓存 |

### 2.1 账号
| 接口 | 方法 | 说明 | 注意 |
|---|---|---|---|
| `/auth/login` | POST | wx.login 的 code → `code2session` 换 openid → 签 JWT | code 一次性，5 分钟有效；并发重复登录幂等 |
| `/auth/phone` | POST | 手机号快速验证组件的 code 换手机号并绑定 | **一手机号一账号**；解密在服务端 |
| `/user/profile` | GET/PUT | 昵称、头像、身份标签（在校生学号/校友/川农好友） | 昵称等 UGC 过 `msgSecCheck` 内容安全接口；学号格式仅校验不强验真 |

### 2.2 牛 / 地图
| 接口 | 方法 | 说明 | 注意 |
|---|---|---|---|
| `/cows` | GET | 当日已上线牛列表（id、激活状态、皮肤、是否铁牛加成、**位置字段分级**） | **未上线的牛绝不下发**（防提前蹲点）；**未激活牛只下发模糊区域**（区域名 + 区域圆心 + 半径，如"图书馆附近/300m"），**精确坐标永不出服务端**；已激活牛可下发精确坐标供地图展示 |
| `/cows/:id` | GET | 牛详情 + 随机一段校史卡片内容 | 未激活的牛也返回校史内容（策划要求：每次互动都有教育输出），但同样不含精确坐标 |
| `/activations` | POST | 激活：上送 `{ lat, lng, photoId, requestId }`，**不传牛 id** | **本清单核心**：服务端在已上线牛中按定位匹配（见 §3 第 1 条）；后到者同样激活得主卡、记录前 10 名到场（策划要求）；照片此时仅作留证"合影" |
| `/upload/photo` | POST | multipart 直传激活照片 → 返回 `photoId` | 仅登录用户；单文件 ≤5MB，仅收 jpg/png/heic；**服务端转码压缩到 ≤300KB webp 再落盘**（原图即弃，省 90% 磁盘）；Nginx `client_max_body_size 6m`；上传频控 10 次/人/天 |

### 2.3 喂养 / 草
| 接口 | 方法 | 说明 | 注意 |
|---|---|---|---|
| `/cows/:id/feed` | POST | 喂草 `{ amount, requestId }` | 条件更新防负数：`UPDATE users SET grass=grass-? WHERE id=? AND grass>=?`；铁牛 ×1.5 加成在服务端按牛配置算；返回随机校史金句 |
| `/grass/checkin` | POST | 每日签到，随机得 20~50 草 | Redis 日 key 限 1 次；随机数服务端生成 |
| `/grass/steal/targets` | GET | 今日可偷的 12 人名单 | 每日凌晨 cron 随机生成写 Redis；名单**随机化、不可指定**（隐私合规要求） |
| `/grass/steal/:userId` | POST | 偷草 | 每人每日 ≤5 次（Redis 计数）；被偷者余量条件更新；偷取量服务端随机 |
| `/grass/log` | GET | 草的收支流水 | 对账用 |

### 2.4 图鉴 / 荣誉
| 接口 | 方法 | 说明 | 注意 |
|---|---|---|---|
| `/cards` | GET | 我的卡片（人物/事件/科研/院系/精神 五类 + 集齐进度） | 发卡动作在激活/事件内同事务完成，不单独暴露"发卡"接口 |
| `/cards/:id` | GET | 卡片内容详情（标题/正文/分类/配图 URL） | 图鉴翻卡用；**卡片文案与历史照片属内容数据，连图带文走接口**（图存服务器由 Nginx 出），管理端可改、勘误不发版；列表页下发缩略图 URL，详情页才给原图 |
| `/badges` | GET | 徽章/头像框/证书状态 | 集齐判定服务端结算 |
| `/rank/feed` | GET | 喂草榜（总榜/院系榜/川农好友榜） | Redis ZSET；返回 TopN + 我的排名；**榜单结果缓存 30~60s** 抗刷新 |
| `/wall` | GET | H5 数字纪念墙数据（120 首发名单） | **免登录只读**，单独限流；给 H5 静态页用，加 CDN 缓存 |

### 2.5 管理端（内部，独立鉴权）
| 接口 | 说明 |
|---|---|
| `/admin/cows` CRUD | 牛的录入（经纬度来自前端标定工具反解 + 区域名）、上线时间/周几时段规则、铁牛加成标记。**模糊圆心在录入时由服务端生成并固化入库**：真实坐标加随机偏移（保证真点在圆内但不在圆心，半径 200~400m）；**禁止每次请求实时随机**——多次采样求平均可还原真点 |
| `/admin/config` | PUT | 更新 `/config` 内容（标定数据、阈值、阶段开关） |
| `/admin/cows/import` | 批量导入坐标 JSON |
| `/admin/audit/photos` | 激活照片抽查列表 + 违规撤销激活 |
| `/admin/stats` | 日活/激活数/喂草数大盘 |

## 3. 激活接口防作弊（重点逐条实现）

1. **服务端匹配牛（不信任客户端指定）**：客户端只上报自身定位，服务端在"已上线"牛中找 Haversine ≤ 50m 的最近一头（阈值进 `/config`，现场调试可放宽到 80m）；同时命中多头取最近；无命中返回 `NO_COW_NEARBY`——**失败响应不携带任何距离/方位提示**（防三角定位扫描逼出牛的精确坐标）
2. **每日 1 次激活成功**：Redis `act:{userId}:{yyyyMMdd}`，过期次日零点；另设**尝试次数上限**（含失败）20 次/人/天，拦虚拟定位网格扫图
3. **首发唯一性**：`SETNX first:{cowId}` 抢锁成功者才写"首发激活人"，DB 落库与 Redis 锁同事务语义（锁成功→DB 唯一索引兜底）
4. **移动速度异常**：记录用户最近一次上报坐标+时间，本次距离/时间差 > 25m/s（≈90km/h）直接拒绝并记风控日志（拦虚拟定位瞬移）
5. **照片留证**：`photoId` 必须存在、归属当前用户、且未被其他激活记录占用（一照一用）；**不做图像识别**，靠后台抽查
6. **同设备多账号**：手机号一号一账号已是主防线；可选记录 deviceId 聚类分析，不上付费指纹 SDK
7. 激活成功的发卡、海报数据（第 N 只、前 10 名到场者）在**同一事务**内产出，避免补偿逻辑

## 4. 数据与并发要点

- **核心表**：`users`、`cows`（含上线规则/加成系数）、`activations`（唯一索引 `cow_id+user_id`、首发唯一索引 `cow_id+is_first`）、`grass_logs`（流水）、`cards`、`feeds`
- 所有资产变更**先写流水再改余额**，同事务；余额异常可由流水重算
- 排行榜：写时 `ZINCRBY`，读走缓存；活动结束后从 DB 流水重算一次作为最终公示版（防 Redis 与 DB 漂移）
- 定时任务（容器内 cron 或 node-cron）：
  - 每日 00:00 生成偷草名单、重置日限
  - 按策划阶段表（预热/主体/高潮/收尾）调度牛上线，支持"周几/时段"规则
- 压力预估：1~3 万用户、校庆当天峰值数百 QPS——单机 4C8G + 上述缓存足够，**不要过度设计**
- **存储预估（照片落本地盘）**：压缩后 300KB/张 × 上限 20 张/人/天，按 3 万用户活动期实际量估 ≈ 10~30GB，数据盘 ≥100GB 即可；照片目录按日期分层 `/data/photos/{yyyyMMdd}/{photoId}.webp`，挂持久化卷，**禁止存容器层**
- **带宽预估（自托管静态资源的第一瓶颈）**：地图瓦片 + 皮肤雪碧图首次进入约 5~8MB/人，校庆当天若 5000 人集中访问 ≈ 30GB 流量；轻量服务器 5~10Mbps 固定带宽**必然被打满**。三选一：① Nginx 前面套按量 CDN（推荐，回源自己的域名，几十元/月）；② 升级按量计费带宽；③ 静态资源域名独立出来方便随时切 CDN。同时 Nginx 对静态资源开 `Cache-Control: max-age=2592000` + 文件名带版本号

## 5. 安全与合规

- [ ] 所有 UGC（昵称、留言类字段）过微信 `msgSecCheck`
- [ ] 定位/拍照权限仅在激活流程触发，接口不静默收集轨迹（隐私合规）
- [ ] 偷草名单随机生成、不可搜索指定用户（防社交骚扰，策划明确要求）
- [ ] 接口全局限流（IP + userId 双维度），登录接口单独更严
- [ ] **备份必须异机**：MySQL 每日 dump + 照片目录增量（rsync/restic）推到另一台机器或网盘，本机快照不算备份；激活/首发等关键操作打审计日志
- [ ] 照片访问需鉴权（本人 + 管理端可见），**不要把 `/data/photos` 整目录公开**，Nginx 内部重定向（`X-Accel-Redirect`）经 API 鉴权后出图
- [ ] 海报二维码/分享参数服务端签名，防伪造"首发海报"
