# 后端反馈：关于《后端接口开发注意清单》

> 回复对象：《后端接口开发注意清单.md》（前端交付）
> 回复时间：2026-06-12
> 结论：清单整体质量很高，防作弊一节（§3）尤其有价值。大部分要求已实现或本次已补齐；少数条目因后端运行在`LinaPro`插件宿主架构上（非清单假设的独立 Docker Compose 部署），实现方式不同但效果等价；另有几条需要前端确认后再排期。请重点看「待前端确认」一节。

| 清单条目 | 后端落地 |
|---------|---------|

## 二、清单已满足项（此前版本即已实现）

- §3.1 服务端匹配牛：客户端只传`lat/lng`不传牛 id，服务端在已上线牛中按 Haversine 取最近一头，阈值默认 50 米且运营端可调；失败响应不携带任何距离/方位提示。
- §3.2 每日 1 次激活成功：业务校验 +（`user_id`,`activity_date`）唯一索引双保险。
- §3.3 首发唯一性：事务内`SELECT ... FOR UPDATE`行锁串行化 + 唯一索引兜底，并发压测有专项测试；后到者同样激活得主卡并记录到场顺序`orderNo`（前 10 名可由`orderNo`直接判定）。
- §3.7 同事务产出：激活记录、牛状态翻转、到场顺序、尝试审计在同一事务内完成。
- §2.3 喂草/签到/偷草：余额条件保护（行锁 + 余额校验同事务）、铁牛 ×1.5 服务端计算、随机校史金句、签到 20~50 随机、偷草 12 人名单每日确定性生成（同日稳定、不可指定、不可搜索）、每日 ≤5 次。
- §1 数值服务端计算：草量、加成、偷取量全部服务端产生，前端上送数值不采信。
- §1 错误码：统一`{code, message, data}`包裹并附语义化`errorCode`（如`PLUGIN_SICAU_NIU_ACTIVATION_DAILY_LIMIT`），见接口文档「统一响应」。
- §4 先写流水再改余额：草料变更与流水在同一事务，余额可由`grass_txn`流水重算。
- §2.4 纪念墙免登录只读、榜单 TopN+我的排名、徽章/证书集齐服务端结算。
- §5 偷草名单随机、不可搜索指定用户。

## 三、实现方式与清单不同、但效果等价的点（请知悉）

后端不是独立 Docker Compose 服务，而是`LinaPro`平台的源码插件，由宿主统一提供数据库、配置、文件上传与静态资源服务。以下条目据此做了等价替换：

- **Redis 相关（日限 key、SETNX 首发锁、偷草名单 key、榜单 ZSET）**：插件当前零 Redis 依赖，统一用 PostgreSQL 唯一索引、行锁与事务实现。清单 §4 自己也写了「1~3 万用户、峰值数百 QPS，不要过度设计」——这个量级 DB 方案足够，且少一个故障组件。榜单当前为 DB 侧聚合 + TopN 限制，如压测不达标再加缓存层。
- **分页**：玩家端所有列表都是有界小结果集（榜单 TopN、最近 10 条喂草、12 人偷草名单、消息分页），不存在深翻页场景，故使用平台统一的`pageNum/pageSize`而非 cursor。若后续出现真正的无界列表再引入 cursor。
- **JWT 静默续期**：玩家 token 有效期 7 天（可配），无单独续期端点。小程序收到`TOKEN_EXPIRED/TOKEN_INVALID`时静默重新`wx.login`换发即可（用户无感知），效果等价于续期，请前端按此处理 401 分支。
- **接口路径**：实际路径带插件前缀（如`/plugins/sicau-niu/player/activations`），清单中的短路径（`/activations`）视为语义示意，完整路径以《小程序接口文档.md》为准。
- **运营配置**：清单把阈值放在`/config`启动下发；实际实现为运营端运行时规则（`LBS`判距、尝试上限、速度上限、签到/偷草/赠草参数、榜单 TopN 等 18 项），改完即对下一个请求生效，比发版配置更灵活。

## 四、需要指出的设计问题与风险提醒

1. **铁牛坐标系（清单未覆盖，风险高）**：清单要求全链路`GCJ-02`，但铁牛实时坐标来自 IOT 太阳能定位器平台，定位器输出大概率是`WGS-84`原始 GPS。铁牛加成判距阈值只有 12 米，而两个坐标系在国内偏差可达 50~500 米——若不转换，加成判定会完全失效。请前端/硬件侧帮忙确认 IOT 平台返回的坐标系；若确认为`WGS-84`，后端将在定时同步入库时做`WGS-84 → GCJ-02`转换。
2. **照片上传方案与清单不一致（§2.2 `/upload/photo`）**：插件复用宿主统一文件上传能力，没有实现专用上传端点，也没有「服务端转码 ≤300KB webp、原图即弃」流程；激活请求中的`photoPath`是已上传文件的路径字符串。清单中的单文件 ≤5MB 限制、格式白名单、上传频控、照片归属校验、一照一用、照片访问鉴权（`X-Accel-Redirect`）目前均未实现。运营端已有照片抽查入口（激活记录可预览原图）。这是双方差异最大的一条，需要对齐：是按清单补专用上传链路，还是接受「宿主上传 + 运营端抽查」的降级方案。
3. **失败响应提示**：清单 §3.1 的「失败不带距离提示」我们严格执行了，连「附近无牛」和「超出判距」对玩家也是同一个错误码`NO_NEARBY_NIU`语义（区分只存在于运营端审计），请前端文案不要试图区分这两种失败。
4. **`/cows/:id`牛详情接口**：清单要求未激活的牛也返回校史卡片内容（教育输出）。当前没有独立详情接口：卡片在激活时发放、图鉴接口可查已获得卡片。若策划确认「未激活也要展示校史内容」，请前端提供交互稿，后端再补详情接口，并注意未上线牛仍然绝不下发。
5. **`msgSecCheck`内容安全（§5）**：昵称等 UGC 的微信内容安全检查尚未实现（需要 access_token 管理链路），后端已列入待办；上线前必须补齐，否则有平台合规风险。
6. **全局限流（§5）**：插件内已有业务级限次（激活/尝试/偷草/赠草/签到），IP + userId 维度的全局限流建议放在入口网关（Nginx/宿主中间件）层实现，属于部署项，请部署清单收录。
7. **§0 上线前置与 §4 带宽/备份**：备案、合法域名、CDN、数据盘与异机备份均为部署运维项，不在插件代码范围内，建议单独建部署核对清单跟踪，避免散落在接口文档里。

## 六、给前端的对接变更摘要

- 喂草/偷草/赠草请求体新增可选`requestId`；网络超时重试时带同一个键，收到`*_DUPLICATE_REQUEST`视为已成功并刷新余额。
- 激活接口新增两个失败错误码：`PLUGIN_SICAU_NIU_ACTIVATION_ATTEMPT_LIMIT`（今日尝试过多）、`PLUGIN_SICAU_NIU_ACTIVATION_SPEED_ANOMALY`（移动速度异常），请配置对应文案；两者均不会附带距离信息。
- 所有每日限次按北京时间零点重置。
- `wx.getLocation`必须使用`type: 'gcj02'`。
